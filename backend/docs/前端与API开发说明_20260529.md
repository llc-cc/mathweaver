# MathGraph 前端 & API 开发说明

---

## 这是什么，能做什么

MathGraph 是一个把数学教材文本转化为**可交互知识图谱**的工具。你把一段数学讲义（Markdown 或纯文本）丢进去，它会自动识别其中的定义、定理、引理、例子等知识节点，分析它们之间的依赖和引用关系，最终生成一张带箭头的关系图。

**主要用途：**
- 快速摸清一本数学教材的知识结构和行文脉络
- 点击任意节点查看原文、逻辑结构（条件/结论）、形式化指导
- 点击边查看两个概念之间关系的描述和强度
- 切换"线性"视图，按书中出现顺序从上到下排布节点，直观看清行文思路
- 登录后自动保存历史，随时重新查看之前处理过的图谱

**支持的输入：** `.md` / `.txt` 文件，或直接粘贴文本  
**需要自备：** 任意兼容 OpenAI 格式的 LLM API（如 DeepSeek、GPT-4 等）

---

## 快速开始

**前置条件：** Python 3.10+、Node.js 18+、一个 LLM API Key

```bash
# 1. 进入项目根目录
cd pdfPipeline

# 2. 一键启动后端（:5001）+ 前端（:5173）
./start.sh
```

启动后打开浏览器访问 **http://localhost:5173**，按以下步骤操作：

1. 点击右上角「登录 / 注册」创建账号（可选，登录后结果自动保存）
2. 拖入或粘贴你的数学讲义文本
3. 展开「LLM 配置」，填写 API URL、模型名和 Key
4. 点击「开始分析」，等待 13 个阶段依次完成（约 2–10 分钟，取决于文本长度）
5. 分析完成后自动跳转到图谱页面，点击节点或箭头查看详情

> **提示：** 如果重启了服务，之前的图谱结果可从右上角「历史」面板重新加载（需登录）。

## 一、项目背景

MathGraph 是一个将中文数学教材（Markdown / 纯文本）通过 13 阶段 LLM 流水线处理，最终生成可交互知识图谱的工具。本次开发在原有后端流水线基础上，**从零搭建了完整的前后端交互系统**，包括：

- 一个 Flask RESTful API（`api_v2.py`）负责接收文件、运行流水线、管理用户和历史
- 一个基于 React Router v7 + Vite 的单页前端（`home.tsx` + `mathgraph.css`）负责图谱可视化与交互

## 二、后端 `api_v2.py`

### 2.1 整体结构

| 层次 | 说明 |
|------|------|
| Flask + Flask-CORS | HTTP 服务，端口 5001，允许前端跨域访问 |
| SQLite (`auth.db`) | 本地持久化：用户、会话、历史记录 |
| 内存 `_jobs` 字典 | 运行中/已完成的任务（进程内，重启后清空） |
| 后台线程 | 每个任务在独立线程运行全部 13 个流水线阶段 |

### 2.2 API 端点一览

#### 认证（无需登录也可使用图谱，登录后可保存历史）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v2/auth/register` | 注册（email + 密码，至少 6 位） |
| POST | `/api/v2/auth/login` | 登录，返回 Bearer token |
| POST | `/api/v2/auth/logout` | 注销当前 token |
| GET  | `/api/v2/auth/me` | 返回当前用户信息 |

#### 任务（流水线）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v2/jobs` | 提交 `.md`/`.txt` 文件 + LLM 配置（`multipart/form-data`），返回 `job_id` |
| GET  | `/api/v2/jobs/<job_id>/status` | 轮询任务状态：`running` / `done` / `error`，含进度（当前阶段、已完成阶段数） |
| GET  | `/api/v2/jobs/<job_id>/result` | 获取图谱 JSON（nodes + edges） |
| POST | `/api/v2/export/<job_id>` | 生成独立 HTML 文件供下载 |

#### 历史记录

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/v2/history` | 列出当前用户最近 50 条记录 |
| POST | `/api/v2/history` | 将指定 `job_id` 的结果保存到数据库 |
| GET  | `/api/v2/history/<id>` | 读取一条历史记录的完整 nodes + edges |
| DELETE | `/api/v2/history/<id>` | 删除一条历史记录 |

### 2.3 数据清洗：`_normalize_nodes` / `_normalize_edges`

流水线输出的原始 JSON 存在多种格式问题，API 层统一做了清洗：

**`_clean_str`**：去除 Python 原始字符串标记（`r"""..."""`）和流水线占位符（`@@CMD::`）。

**`_normalize_nodes`**：
- 从 `title.chinese` / `title.english` 中提取中英文标题
- 从 `remark.original_form` 等多级嵌套路径提取 `content`
- 保留 `global_id`（MD5 哈希）、`node_type`、`statement_form`、`formalization_guidance` 等字段
- 为每个节点分配顺序整数 `id`（0, 1, 2, …）

**`_normalize_edges`**：
- 关键修复：`build_relations` 阶段用 `global_id`（MD5）而非标题作为节点标识符，旧代码匹配失败导致始终 0 条边
- 改为先建 `gid_map`（`global_id → id`），以标题名作为 fallback

### 2.4 SQLite 数据库 Schema

```sql
CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    email         TEXT    UNIQUE NOT NULL,
    password_hash TEXT    NOT NULL,   -- werkzeug pbkdf2 哈希
    created_at    TEXT    NOT NULL
);
CREATE TABLE sessions (
    token      TEXT    PRIMARY KEY,   -- secrets.token_hex(32)
    user_id    INTEGER NOT NULL,
    created_at TEXT    NOT NULL
);
CREATE TABLE history (
    id          TEXT    PRIMARY KEY,   -- 与 job_id 相同
    user_id     INTEGER NOT NULL,
    filename    TEXT    NOT NULL,
    node_count  INTEGER NOT NULL DEFAULT 0,
    edge_count  INTEGER NOT NULL DEFAULT 0,
    nodes_json  TEXT    NOT NULL,
    edges_json  TEXT    NOT NULL,
    created_at  TEXT    NOT NULL
);
```

## 三、前端 `home.tsx` + `mathgraph.css`

技术栈：React Router v7（SSR 模式）、Vite、Tailwind CSS v4、vis-network、KaTeX。

### 3.1 页面状态机

```
upload  →  processing  →  result
  ↑                         ↓
  └─────────── error ←──────┘
```

- **upload**：文件拖拽/粘贴 + LLM 配置（API URL、模型名、API Key）
- **processing**：轮询 `/status`，展示 13 阶段进度条
- **result**：vis-network 知识图谱 + 节点/边详情抽屉
- **error**：报错信息 + 已完成阶段 + 可选查看部分结果

### 3.2 会话持久化

- **`localStorage`**：保存登录 token 和 email，跨标签页保持登录状态
- **`sessionStorage`**：保存最近一次图谱结果（`nodes + edges + filename + jobId`），防止意外刷新丢失数据
- 所有 storage 访问均有 `typeof window === "undefined"` SSR 守卫

### 3.3 图谱可视化（vis-network）

#### 节点颜色映射

| 节点类型 | 颜色 |
|----------|------|
| 定义 | #3B6FBF（深蓝） |
| 定理 | #2E7D5E（深绿） |
| 引理 | #5B8E78 |
| 推论 | #6B5B9E |
| 公理 | #7A6B4A |
| 性质 | #4A7A8E |
| 命题 | #8E6B4A |
| 例子 | #7A8E4A |

#### 物理引擎控制

vis-network 的 forceAtlas2Based 布局在初始稳定后会自动停止（`stabilizationIterationsDone` 事件），并有 4 秒超时兜底，防止图谱永久旋转：

```typescript
net.once("stabilizationIterationsDone", () => net.setOptions({ physics: false }));
const killTimer = setTimeout(() => net.setOptions({ physics: false }), 4000);
```

#### 两种视图模式

| 模式 | 说明 |
|------|------|
| **图谱**（默认） | force-directed 自由布局，物理引擎稳定后静止 |
| **线性** | 按文档顺序从上到下排布节点（之字形：偶数节点 x=-180，奇数节点 x=180，y 间距 200px），物理关闭，自动 fit |

#### 高度滑块

页面右边缘固定一个垂直滑块（200–1200 px），通过**直接操作 DOM**（`graphRef.current.style.height`）调整 canvas 高度，完全绕开 React 状态更新，无重渲染无闪烁。页面挂载后自动测量实际 CSS 高度并同步滑块位置和数字标签。

### 3.4 LaTeX 渲染

#### `labelText()`：vis-network 画布标签

canvas 只能渲染纯文本，函数将 LaTeX 转换为 Unicode：
- 剥除 `$...$`、`\(...\)`、`\[...\]` 定界符
- `\mathbb{R}` / `\text{foo}` 等命令展开为内部内容
- 符号映射：`\infty→∞`、`\alpha→α`、`\to→→`、`\leq→≤` 等 50+ 条规则
- 剩余 `\cmd` 删除，`{}` 删除，空白归一化

#### `preprocessLatex()`：KaTeX 预处理

将流水线生成的非标准命令规范化后再交给 KaTeX：

| 原始命令 | 转换结果 |
|---------|---------|
| `\Abs{x}` / `\Abs(x)` | `\|x\|` |
| `\Norm{x}` | `\|\|x\|\|` |
| `\Map` | `\mathrm{Map}` |
| `\ConvergesTo` | `\to` |
| `\Limit` | `\lim` |
| `\VSubset` | `\Subset` |
| `\joinrel` | （删除） |
| `\text{Equivalence}` | `\leftrightarrow` |
| `\text{Implication}` | `\Rightarrow` |
| `\operatorname*` | `\operatorname` |

#### `parseMathSegments()`：混合文本分割

将含数学的文本按 `$...$`、`\(...\)`、`$$...$$`、`\[...\]` 分割为交替的 text/math 段，再分别渲染。

重要修复：`\(...\)` 正则原为 `[^)]+?`（不允许内部括号），改为 `[\s\S]+?`，修复了含 `(U)` 等括号的公式（如 `C_c^{\infty}(U)`）渲染失败的问题。

#### `SmartTitle`：无定界符标题

部分节点标题含 `W^{k,p}` 等表达式但没有 `$` 包裹。`SmartTitle` 组件的处理逻辑：
- 有 `$` / `\(` / `\[` → 交给 `MathText`（KaTeX 渲染）
- 否则 → 交给 `labelText()`（Unicode 转换，始终可读）

### 3.5 交互功能

#### 节点点击
右侧抽屉展示：节点类型徽章、中英文标题（SmartTitle）、原文（MathText）、逻辑结构（主语/条件/结论）、证明提示、形式化指导（命题骨架、语义风险、概念提示）。

#### 边点击
同一抽屉位置显示关系信息：关系名称、强度（强/中/弱，颜色区分）、两端节点名（蓝色标签），以及关系解释文本。

#### 节点类型过滤
左侧边栏可按类型勾选/取消节点，联动更新图谱（同步过滤边）。

### 3.6 账号系统

- 邮箱 + 密码注册/登录（本地 SQLite，密码 pbkdf2 哈希存储）
- 登录后图谱处理完成自动保存到历史
- 历史面板：列出最近 50 条，支持重新加载和删除
- 未登录用户可正常使用图谱，但结果不持久化

## 五、关键 Bug 修复记录

| Bug | 根因 | 修复方式 |
|-----|------|---------|
| 始终 0 条边 | `build_relations` 用 `global_id`（MD5）标识节点，旧代码按标题匹配 | `_normalize_edges` 优先用 `gid_map[global_id]` 匹配 |
| 图谱永久旋转 | vis-network forceAtlas2 稳定后不自动停止 | `stabilizationIterationsDone` 事件 + 4 秒超时 |
| 节点标签显示 `\infty` | vis-network canvas 不支持 LaTeX | `labelText()` 函数转 Unicode |
| 刷新丢失结果 | 无前端持久化 | `sessionStorage` 缓存 graph JSON |
| SSR 崩溃 | Node.js 环境无 `window`，`localStorage` 报错 | 所有 storage 访问加 `typeof window === "undefined"` 守卫 |
| `r"""..."""` 出现在内容中 | 流水线输出包含 Python 字符串字面量标记 | `_clean_str()` 中正则剥除 |
| `\(C_c^{\infty}(U)\)` 不渲染 | 正则 `[^)]+?` 遇到内部括号就停 | 改为 `[\s\S]+?` |
| 高度滑块拖动闪烁 | `setGraphHeight` 触发 React 全量重渲染 | 改用 `ref` 直接操作 DOM，零重渲染 |
| 代理环境 LLM 调用失败 | 系统 `ALL_PROXY` 让 httpx 走本地代理 | `api_v2.py` 启动时主动 `pop` 所有代理环境变量 |
