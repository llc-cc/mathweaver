# Formalizer v3 形式化语义正确性对比实验报告

## 一、实验背景与目的

本实验旨在对比 `formalizer_v3` 两种输入方式对数学命题形式化结果的影响：

- **方式1（原始陈述）：** 仅使用 `split_data.json` 中的 `statement` 字段
- **方式2（完整JSON）：** 使用 `TEST_NODE_OUT(1).json` 中的全部字段（标题、标签、类型、内容、标准化形式等）

## 二、实验设置

### 2.1 测试环境

- **模型：** qwen3-max（aihubmix.com）
- **Formalizer 版本：** formalizer_v3
- **Lean 服务器：** Kimina Lean Server via Docker
- **测试数据：** 42 条线性代数命题

### 2.2 提示词核心约束

```
1. ONLY ONE declaration - 只输出一个定义/定理
2. Use existing Mathlib - 优先复用 Mathlib 已有定义
3. No proofs - 定义不需要 := by sorry
4. Be concise - 保持简洁
```

### 2.3 两种方式对比

| | 方式1 | 方式2 |
|--|-------|-------|
| 输入内容 | 仅 `statement` 字段 | 标题(CN/EN) + 标签 + 原始类型 + content + original_form + subject |
| 平均输入长度 | ~300-400 字符 | ~400-600 字符 |
| 提示词占比 | 70-80% | 70-80% |

## 三、实验结果

### 3.1 总体统计

| 指标 | 方式1 | 方式2 |
|------|-------|-------|
| 编译成功率 | 40/42 (95.2%) | 41/42 (97.6%) |
| **严格语义正确率** | 29/42 (69.0%) | 32/42 (76.2%) |
| 编译失败数 | 2([19,31]) | 1([19]) |
| 语义错误数 | 10 | 8 |
| 上下文不当 | 1([40]) | 1([34]) |
| 总问题数 | 13 | 10 |
| 平均输入Token | 1016 | 1070 |
| 平均耗时 | 5.4s/条 | 5.3s/条 |

> **注：** 严格语义正确 = 编译成功 **且** 语义完全正确

### 3.2 按类型成功率

| 类型 | 方式1 | 方式2 |
|------|-------|-------|
| 定义(def) | 91% | 91% |
| 注释(rem) | 100% | 100% |
| 命题(prop) | 96% | 100% |

| 索引 | 标题 | 错误原因 |
|------|------|---------|
| [3] | 子集的数乘封闭性 | 命名为 `IsSubspace`，但原始只陈述条件(2)，泛化过度 |

**共性原因：** 输入信息少时，AI 倾向于过度泛化或选择不合适的 API。

| 索引 | 标题 | 错误原因 |
|------|------|---------|

- **方式2（错误）：** 引入 `2•β` 和复杂的 Finset 构造 — 被标题中的"极大线性无关"干扰

### 4.6 上下文不当的2条分析

这两个案例的形式化在数学上正确，但 API 选择不符合"向量组秩"的标准表达。

| 索引 | 标题 | 方式1 | 方式2 |
|------|------|-------|-------|
| [34] | 向量组线性无关与秩的关系 | `Module.rank` ✓ | `Matrix.rank` (上下文不当) |
| [40] | 向量组秩相等的例子 | `Matrix.rank` (上下文不当) | `Module.rank` ✓ |

**说明：** `Matrix.rank` 和 `Module.rank (Submodule.span ...)` 在具体例子中数学等价，但向量组秩的标准定义是后者。

#### 典型案例：[40] 向量组秩相等的例子

**原始命题：**
```
例如,α₁=(1,0,0), α₂=(0,1,0); β₁=(1,0,1), β₂=(0,1,1)
于是 rank{α₁,α₂} = rank{β₁,β₂}
```

**方式1（上下文不当）：**
```lean
Matrix.rank ![α₁, α₂] = Matrix.rank ![β₁, β₂]
```
- 数学上正确（矩阵行秩 = 2）
- 但"向量组秩"的标准表达应该是 `Module.rank (Submodule.span ...)`

**方式2（标准表达）：**
```lean
Module.rank ℝ (Submodule.span ℝ {α₁, α₂}) = Module.rank ℝ (Submodule.span ℝ {β₁, β₂})
```
- 符合向量组秩的标准数学定义
- 先构造子空间，再求维数

---

#### 重点案例：[37] OCR 识别错误

- **原始 JSON：** "获相等的两个向量组不一定等价"
- **正确原文：** "**秩相等的**两个向量组不一定等价"
- **影响：** OCR 错误导致命题本身无数学意义，两种方式都无法正确形式化

## 五、提示词修改建议

### 5.1 可通过提示词解决的问题

#### 问题1：蕴含 vs 合取（[39]）
**建议增加：**
```
对于"例如"类命题:
- 用 ∧ 连接所有需要同时成立的条件
- 不要用 →（那是蕴含，不是例子描述）
```

#### 问题2：API 选择（[40]上下文不当案例）
**说明：**
- 方式1使用 `Matrix.rank` 在数学上正确，但不符合向量组秩的标准表达
- 方式2使用 `Module.rank` 更符合数学定义
- 两者在具体例子中数学等价

**建议增加：**
```
向量组的秩优先使用: Module.rank K (Submodule.span K (Set.range v))
矩阵的秩使用: Matrix.rank
两者不要混用，但需注意数学上可能等价
```

#### 问题3：过度泛化（[3]）
**建议增加：**
```
当命题只陈述部分条件时:
- 使用描述性的名字，如 ScalarMultiplicationClosed
- 不要上升到更一般的概念（如 IsSubspace）
```

### 5.2 难以通过提示词解决的问题

| 问题类型 | 案例 | 原因 |
|---------|------|------|
| 几何概念形式化 | [10][11] | "共面"等概念没有标准数学定义，需要更多上下文 |
| 复杂数学构造 | [26] | 极大线性无关组等价需要深层数学理解 |
| 元数学命题 | [21] | "反身性"等描述不是直接的形式化目标 |
| 数据错误 | [37] | OCR 识别错误导致命题本身无意义 |
| 上下文不当 | [34(方式2)][40(方式1)] | API选择数学上等价但非标准表达 |

### 5.3 建议的提示词补充

```markdown
## 补充约束

### 几何概念形式化
当命题涉及几何概念时:
- 共面三个向量: 存在不全为零的k₁,k₂,k₃使得k₁α+k₂β+k₃γ=0
- 共线两个向量: ∃k, α = k•β ∨ β = k•α

### 例子类命题
对于"例如"类命题:
- 使用 ∧ 连接所有需要同时成立的条件
- 不要用 →

### API 选择
- 向量组的秩: `Module.rank K (Submodule.span K (Set.range v))`
- 矩阵的秩: `Matrix.rank`
- 两者不要混用

### 构造优先级
- 优先使用简洁的数学表达

```

## 六、结论

1. **方式2略优：** 76.2% vs 69.0% 严格语义正确率，主要优势在于编译失败率更低

2. **各有优劣：** 5条方式1独有错误 vs 3条方式2独有错误，没有一方完全优于另一方

3. **上下文不当问题：** 2条 [34(方式2), 40(方式1)] 属于 API 选择非标准但数学上等价的情况

4. **主要错误来源：**
   - 方式1：输入信息少导致泛化过度或 API 选择错误
   - 方式2：输入信息多导致上下文干扰或过度构造
