一、引入与问题提出
很多时候，系统失败并不是因为模型完全不会写 Lean，而是因为输入的自然语言数学文本本身就不够“适合形式化”。
更具体一点说，数学自然语言里经常会有这样几类情况：
- 变量类型没有写清楚；
- 前提条件是默认的，没有显式说明；
- 某些定义虽然在人的理解里是自然调用的，但对机器来说并没有真的出现；
- 证明中经常有“显然”“由此可得”“注意到”这样的跳步。
对人来说，这些内容可以依靠背景知识自动补足；但对形式化系统来说，这些地方恰恰就是最容易断掉的地方。
能不能先把自然语言数学文本处理得更致密、更完整、更结构化，再把它交给后续形式化系统？
这个项目想做的就是自动形式化之前的一层“桥”。

---
二、项目定位与核心想法
本项目定位于自动形式化流程中的前处理桥梁层。其核心目标不是直接生成 Lean 代码，而是在自然语言侧先完成信息补足、逻辑展开和结构规整，将原始数学文本转化为一种更适合后续形式化的中间表示。Lean 在本项目中主要承担验证与反馈作用，而不作为系统的核心依赖。
项目的核心目标是构造一种中间表示：它不是原始自然语言，也不是最终的 Lean 代码，而是一种逻辑更清楚、信息更完整、结构更显式的中间层。
从研究脉络上看，本项目与组内已有工作是一条连续的发展线，而不是另起一条路线。ATLAS 主要解决了高质量并行数据不足的问题，通过 Data Lifting、Data Synthesis、Data Augmentation 的三段式框架构建了 117k 的自动形式化并行语料，并在多个数据集上显著优于已有方法，说明数据构造方式本身就是决定 autoformalization 上限的重要因素。
GTED 与 ASSESS 则将重点放在评测侧：前者把 formal statement 转为算子树并用树编辑距离做评估，后者进一步引入语义变换，提出更稳健的结构—语义联合评测指标。这一系列工作表明，数学表达的本质并不是表面字符串，而是其内部结构与运算组织方式。
DSR 在此基础上进一步说明，若能先做分解、结构化建模，再利用局部结构进行修复，则自动形式化的稳定性和精度都可以明显提升。其 tree-guided repair 在多个基准上取得了优于全局修复的结果，说明“先定位局部断点、再做定点补全”比整句重写更适合数学文本。
因此，本项目的核心想法可以概括为：
1. 将自然语言数学文本拆解为条件、定义、结论、中间步骤等逻辑单元；
2. 以 DAG 为核心组织形式，显式表示逻辑依赖与缺口位置；
3. 对缺失信息进行分类，并通过“知识补全 + 推理补全”的双轨方式完成修复；
4. 输出一个逻辑更致密、结构更清晰、可直接服务于形式化系统的中间表示。
简言之，本项目不是直接追求“从自然语言一步到位翻译到 Lean”，而是希望先解决自动形式化之前最根本的问题：自然语言数学文本本身不够致密、不够显式、不够可计算。

---
三、研究价值
1. 问题本身的研究价值
自动形式化的失败，很多时候并不只是模型生成能力不足，而是因为输入侧天然存在大量“隐含逻辑”。在数学自然语言中，变量类型、量词范围、标准前提、定义调用和中间推理常被省略；这些内容对于人类读者而言可以依赖背景知识自动补足，但对形式化系统而言却恰恰是最容易断裂的部分。
因此，本项目关注的不是一般意义上的“文本改写”，而是自然语言数学中的逻辑断层识别与补全问题。若这一层能够做好，则后续知识图谱构建、文档合并和自动形式化都将拥有更稳定的输入基础。
2. 结合近期 SOTA 工作所体现的项目价值
近期的代表性系统进一步说明了这一方向的重要性。
CRAMF 的核心工作是将概念检索显式纳入自动形式化流程，通过从 Mathlib4 构建概念—定义知识库，在生成 formal statement 时先检索相关正式定义，再进行翻译。该方法在 miniF2F、ProofNet 和 AdvancedMath 上均带来一致提升，最高达到 62.1% 的翻译准确率提升，平均相对提升为 29.9%。这说明：很多自动形式化问题本质上不是“不会生成”，而是“缺少概念和定义支撑”。本项目中的“知识补全轨道”正是针对这一痛点展开。(Hugging Face)
M2F 则把问题推进到了更大尺度：它不再处理孤立定理，而是面向整本文献或项目级材料，先做声明骨架编译，再做 proof hole repair，在 479 页教材上自动生成了 153,853 行 Lean 代码，并在 FATE-H 上达到 96% 的 proof success，相比强基线 80% 有显著提升。该工作说明：自动形式化一旦走向真实文档和大规模工程，核心挑战就不再只是单句翻译，而是依赖管理、结构组织与局部修复。本项目所强调的“逻辑致密化中间层”，正可以视为进入此类项目级形式化之前的必要准备。(Cool Papers)
DSR 的贡献则体现在方法论层面。它证明了将自动形式化分解为“语义规范化—结构映射—局部修复”是有效的，并进一步表明 operator tree 所支撑的局部修复优于全局暴力重写。对本项目而言，这一结果的意义在于：自然语言数学中的断层问题同样适合用结构化方式来定位与修复，而不必从一开始就把问题完全绑定在 Lean 内部机制上。
综上，近期 SOTA 共同指向一个判断：自动形式化若想继续提升，必须在“概念补全、结构组织、局部修复”这几个层面引入更强的中间表示与控制机制。本项目正是在这一趋势下提出的系统性补充。
3. 与组内总体目标的关系
本项目与“知识图谱—文档合并—形式化”三项目标有直接衔接关系。
其一，在知识图谱层面，本项目需要显式抽取概念、变量、条件、结论、定义调用和依赖边，因此天然能够沉淀为数学知识图谱中的节点和关系。
其二，在文档合并层面，不同教材或论文中的同类命题往往具有不同表面表述，但其逻辑骨架是相近的。若能将其统一转化为结构化中间表示，则有助于命题对齐、版本融合与知识去重。
其三，在形式化层面，本项目输出的致密表示将比原始自然语言更接近 formalization 所需输入，可直接作为下游 autoformalizer、agentic prover 或 verifier-in-the-loop 系统的前置模块。
因此，本项目并非独立孤立的方向，而是可以作为组内总体目标中的基础接口层与共性支撑模块。

四、研究内容
本项目拟围绕“自然语言逻辑致密化与缺口补全”这一主线开展研究，当前的设计仍属于计划方案，后续将根据实验结果逐步收敛。
1. 定义一种面向自动形式化的中间表示。该表示不直接等价于 Lean，也不只是自然语言改写，而是介于两者之间的结构化逻辑层，显式记录变量及其类型、条件约束、定义调用、目标结论、依赖关系、缺口标签及补全来源。该中间表示将作为项目的核心载体，用于承接后续图建模、补全和评测。
2. 建立自然语言数学文本的DAG 表示。其中，节点表示条件、定义、中间命题、结论等逻辑单元，边表示依赖关系、推理支撑关系和定义调用关系。采用 DAG 的目的，不在于形式上“图化”，而在于把原本隐含的断层转化为显式可操作的问题：例如节点缺失、依赖边缺失、标签缺失或局部子图不闭合。
3. 提出一个鬼节点分类体系。初步设想至少包含三类：定义型鬼节点，对应术语和概念未被完整展开；约束型鬼节点，对应变量范围、对象类型、量词作用域或标准前提缺失；推理型鬼节点，对应证明跳步或中间命题缺失。该分类体系既用于数据标注，也用于路由后续补全方法。
4. 设计双轨补全框架。其中一条轨道负责知识补全，主要面向定义型和约束型鬼节点，预期依赖概念检索、定义检索、小型知识库和 reranking 等工具；另一条轨道负责逻辑补全，主要面向推理型鬼节点，预期依赖 LLM 的局部推理生成能力，在给定上下文子图的条件下补出中间命题或局部论证。
5. 适度引入算子树思想。与完全依赖 Lean 内部 operator tree 机制的方案不同，本项目不会将算子树作为唯一核心表示，而是把它作为表达式级结构先验和评测工具。具体而言，可针对致密表示中的关键表达式构建轻量算子树，用于局部结构对齐、补全候选排序和结构一致性评估。
6. 在数学理论与算法层面，还可保留若干待选方案作为增强方向。例如，可将补全过程建模为一个最小修复问题，在满足逻辑一致性约束的前提下，以最少的节点、边和标签修改完成结构闭合；也可引入局部一致性约束和最短修复路径思想，以避免系统通过大规模重写破坏原始语义。此部分将在项目推进中根据实验结果决定是否作为正式方法展开。
若第一阶段工作顺利，项目的预期交付包括：一套自然语言逻辑致密化原型系统、一套鬼节点分类与补全框架、一个小规模评测集与评测脚本，以及一版能够证明“致密化前处理可提升下游形式化效果”的实验结果。

五、技术路线
本项目拟按“定义任务—构建结构—实现补全—闭环评测”的顺序推进，保证每一阶段都具有明确的中间检查点，而不是在前期长期停留于不可验证的设计阶段。
1. 文献整理、问题定义与样本分析
在这一阶段，将系统梳理组内工作与近期 SOTA 方案，重点总结自动形式化中与概念补全、结构建模、局部修复、检索增强相关的方法路线。同时，选取一批小样本进行人工分析，整理自然语言数学文本中的典型断层模式，形成鬼节点分类初稿和中间表示模板。该阶段的主要工具包括人工阅读、结构化标注、简单 Python 脚本和少量 LLM 辅助归纳。其阶段性产出应是一份问题定义文档、一套标签体系和一批可用于后续开发的小样本。
2. 中间表示与 DAG 原型构建
在这一阶段，将把自然语言文本转化为条件、定义、结论等逻辑角色，并以程序化方式组织为中间表示和依赖图。方法上可以先采用“规则抽取 + LLM 辅助切分”的轻量方案，逐步建立从文本到 DAG 的原型流程。此阶段的关键不是追求完全自动化，而是验证该结构表示是否能够稳定表达数学文本中的主要逻辑关系，以及是否能显式暴露潜在缺口。该阶段可通过小规模样本的图可视化和人工检查来评估效果。（可参考跨文档级数学提取代码）
3. 鬼节点检测与双轨补全实现
在这一阶段，将首先用规则与启发式方法对缺口进行初筛，例如检测概念缺失、类型未定、量词不闭合、结论依赖不足等模式；随后结合轻量分类模型或 LLM 判断鬼节点类别和优先级。之后，根据鬼节点类型路由到两条补全轨道：知识补全轨道主要依赖小型概念—定义库、embedding 检索、reranker 等工具；逻辑补全轨道主要依赖 LLM 在局部上下文中的中间步骤生成能力。该阶段需同步进行中间检查，例如固定样本上的缺口识别准确率、补全后结构完整度变化、是否引入新的逻辑冲突等。
4. 局部修复回写与下游验证
在这一阶段，将前述检测与补全模块组合成闭环系统，从原始文本出发，输出完整的致密中间表示及对应的结构图。之后，将该输出与原始文本共同送入下游 autoformalization 系统或 verifier-in-the-loop 流程，比较两者在通过率、错误日志、修复轮数等指标上的差异。Lean 在这一阶段主要用于提供反馈信号和错误定位，而不是直接参与前端补全策略。此阶段的目标是明确回答：致密化是否真的为下游形式化提供了增益。
5. 系统评测、消融实验与报告整理
在这一阶段，将完成完整实验，比较不同模块配置下的性能变化，包括不使用 DAG、只做表面重写、只做知识补全、只做逻辑补全等设置，并进行误差分析，明确失败案例究竟来自结构抽取不足、检索缺失、推理失败，还是下游形式化器本身的限制。该阶段将同步整理成正式报告和论文初稿所需材料。
从时间安排上，若按 1–2 个月推进，前两周适合完成问题定义与样本分析，第 3–4 周完成原型构建，第 5–6 周完成补全模块和下游验证，第 7–8 周完成评测、消融和报告整理。整体节奏上，每一阶段都设置中间可检查产物，以降低后期大规模返工风险。

六、评测设计
本项目的评测不会只依赖最终的 Lean 编译通过率，而将采用“结构恢复—结构一致性—下游增益”三层评测框架。
第一层是结构恢复评测。即从原本结构较完整的样本中，人工或程序化删除部分节点、边和标签，构造伪鬼节点，再要求系统进行恢复。评测指标包括节点恢复率、边恢复率和标签恢复率。该层主要衡量补全框架本身是否能识别并修复逻辑缺口，是本项目最直接的核心评测。
第二层是结构一致性评测。在这一层中，将不只关注表面文本相似，而是比较补全后的中间表示与参考结构在逻辑组织和表达式结构上的接近程度。这里可结合组内 GTED、ASSESS 的思想，使用 operator tree 或其他轻量结构表示来评估关键表达式和局部逻辑单元的结构匹配程度，从而避免模型给出表面流畅但数学上失配的补丁。
第三层是下游增益评测。即比较原始自然语言输入、表面重写版本、完整致密化补全版本三类输入在下游 autoformalization 流程中的表现差异，观察其对形式化通过率、错误日志类型、平均修复轮数和失败案例分布的影响。只有这一层的结果能够证明本项目的前处理步骤不是孤立有效，而是真正改善了后续形式化任务。
若实验条件允许，还可增加一个鬼节点分类型评测，分别统计定义型、约束型和推理型鬼节点上的检测与补全效果，以明确哪类缺口最具挑战、哪类补全对下游收益最大。这一分析既能帮助系统迭代，也更有利于论文中对方法边界和适用性的说明。

七、人员安排
主要按模块化工作进行人员安排：
1. 数据与标注，主要工作包括样本筛选、致密化真值整理、鬼节点标签构建和评测集制作。
2. 结构表示与工程实现，主要工作包括中间表示设计、DAG 构建、数据处理脚本和可视化分析工具开发。该部分更适合具备 Python 能力和结构化数据处理经验的成员。
3. 检索与知识补全模块，包括概念—定义小库构建、embedding 检索、rerank、知识补全过程设计等。该部分适合具备信息检索、RAG 或文本匹配经验的成员。
4. 逻辑补全与模型实验，包括 prompt 设计、LLM 局部推理实验、候选筛选策略和消融对比等。
5. （刚需）下游验证与误差分析，主要任务是将致密化结果接入后续 autoformalization 流程，读取错误日志，分析失败模式，并判断问题究竟出在前处理、中间结构，还是后端形式化器。这一部分最好有熟悉 Lean / Mathlib 或愿意承担验证接口工作的成员参与。
若需进一步扩充合作者，则最优先补充两类能力：一类是熟悉 Lean 及其验证生态的成员，用于处理后端接口与反馈信号；另一类是熟悉知识图谱或信息抽取的成员，用于增强结构抽取和图表示部分的系统性。

八、总结
本项目拟解决的是自动形式化之前的一层关键问题：自然语言数学文本本身往往不够致密，存在大量隐含前提、定义缺失和推理跳步，而这些恰恰是形式化系统最容易失败的地方。基于这一判断，本项目提出在自然语言端先进行逻辑致密化与缺口补全，再将处理后的中间表示送入后续形式化系统。
本项目拟围绕“自然语言逻辑致密化与缺口补全”这一主线展开，目标是在自动形式化之前增加一层结构化前处理模块。具体而言，项目将首先对自然语言数学文本进行逻辑分解，抽取其中的变量、条件、定义、结论与中间步骤，并构建相应的 DAG 表示；随后围绕图中的缺口设计鬼节点分类体系，将问题细化为定义型、约束型和推理型三类缺失；在此基础上，通过“知识补全”和“逻辑补全”两条轨道，对自然语言中的隐含前提、缺失定义和证明跳步进行定向修复，最终输出适合后续形式化系统使用的致密中间表示。
在技术路线方面，本项目将按照“问题定义与样本分析—中间表示与 DAG 构建—鬼节点检测与双轨补全—下游验证与结构化评测”的顺序推进，并在每一阶段设置可检查的中间产物。评测上，将同时从结构恢复、结构一致性和下游形式化增益三个层面验证方法有效性，避免仅依赖最终编译通过率这一单一指标。预期在 1–2 个月内形成一套可运行的原型框架、一批可复用的小规模数据与评测资源，以及一版能够支撑阶段性论文或项目报告的实验结果。
