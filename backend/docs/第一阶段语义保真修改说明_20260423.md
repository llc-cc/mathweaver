# 第一阶段语义保真修改说明

**修改时间**: 2026-04-23

**对应目标**: 根据三份形式化实验报告中暴露的问题，先实施低成本、高收益的第一阶段修改。重点不是直接重写 formalizer，而是在现有 pipeline 中加入一层可复用的“形式化语义保真 guardrail”，为后续 M1/M2 候选选择、prompt 分层和自动风险复核提供结构化依据。

---

## 一、本阶段做了什么

本阶段新增了一个纯规则模块：

```text
backend/pipeline/common/formalization_guards.py
```

并将其接入节点生成阶段：

```text
backend/pipeline/stages/extract_logic_tuples/stage.py
```

现在每个输出节点会额外带有一个字段：

```json
"formalization_guidance": {
  "primary_statement": "...",
  "statement_skeleton": {...},
  "role_bindings": [...],
  "concept_hints": [...],
  "context_policy": [...],
  "semantic_risks": [...]
}
```

这个字段不会替换原有 `content`、`conditions`、`conclusions` 等字段，而是作为后续形式化、人工检查和组内评估使用的辅助层。

## 二、具体修改方法

### 2.1 M2 输入上下文分层

原问题：M2 使用完整 JSON 时，标题、标签、上下文、标准化形式等字段容易混在一起，导致模型被无关上下文干扰。例如标题里出现“极大线性无关组”，模型可能过度构造极大性条件；代数学定义中也会额外添加非零、正性等题目未要求的条件。

本次实现：

新增 `build_formalizer_context_payload(node)`，把 M2 风格输入分成：

- `primary_statement`: 原始正文，作为最高优先级。
- `auxiliary_context`: 标题、标签、类型、变量、subject、context，只能用于消歧。
- `statement_skeleton`: 逻辑骨架。
- `role_bindings`: 变量角色绑定。
- `concept_hints`: 概念保真提示。
- `context_policy`: 明确禁止标题/标签覆盖正文，禁止添加题目没有的非零、正性、极大性、有限性、严格性条件。

能解决的问题：

- 减少 M2 因标题或上下文字段带来的过度构造。
- 为后续 formalizer prompt 提供标准化输入，而不是直接拼完整 JSON。
- 对应报告1中 M2 的 Item 24、27、41，报告3中 M2 的 Item 9、10、13 等额外条件/上下文干扰问题。

### 2.2 逻辑骨架识别

原问题：模型经常把“当且仅当”写成单向蕴含，把“例如”类命题写成 `→`，把非严格包含链写成严格包含。

本次实现：

新增 `infer_statement_skeleton(node)`，识别以下骨架：

- `definition`: 定义类命题。
- `equivalence`: 当且仅当、充分必要条件。
- `example_conjunction`: 例如、取、于是等例子类命题。
- `non_strict_chain`: `⊆`、`\subseteq`、升链等非严格包含。
- `multi_part`: 进一步、此外、并且、推论等复合命题。
- `existence`: 存在性命题。
- `implication`: 若/如果/则。
- `equality`: 等式命题。

能解决的问题：

- 报告1 Item 39：例子类命题用 `→` 连接，应改为 `∧`。
- 报告2 Item 11、13：不应把等价/并列结构压成单向蕴含。
- 报告3 Item 22：理想升链应使用非严格包含 `⊆`，不是严格包含 `<`。
- 报告3 Item 12、13：多子命题不能被强行合并或漏掉后续推论。

### 2.3 数学概念保真词典

原问题：模型会把关键数学概念替换成“看似相关但语义不同”的 Lean API 或谓词。例如相伴关系被替换为 `IsUnit`，向量组秩被替换为 `Matrix.rank`，最大公因子定义被替换为 `GCDMonoid.gcd`。

本次实现：

新增 `CONCEPT_LEXICON`，第一批覆盖以下概念：

- `associated`: 相伴关系，推荐 `Associated`，避免用 `IsUnit` 替代。
- `vector_family_rank`: 向量组秩，推荐 `Module.rank + Submodule.span`，避免默认 `Matrix.rank`。
- `gcd_definition`: 最大公因子定义，推荐展开共同因子和最大性谓词，避免只用 `GCDMonoid.gcd`。
- `lcm_definition`: 最小公倍数定义，推荐展开公倍数和最小性谓词，避免只用 `lcm`。
- `non_strict_inclusion`: 非严格包含，推荐 `⊆`，避免严格包含。
- `divisibility_roles`: 整除角色，要求区分 divisor 和 dividend。

能解决的问题：

- 报告3 Item 6：不可约元定义应保留相伴关系 `~ / Associated`，不能降级成 `IsUnit`。
- 报告1 Item 34、40 与报告2 Item 34：向量组秩应优先使用生成子空间维数，不默认用 `Matrix.rank`。
- 报告3 Item 9：最大公因子定义不能只调用 `GCDMonoid.gcd`。
- 报告3 Item 11：最小公倍数定义不能只调用 `lcm`。
- 报告3 Item 22：升链不能改成严格包含。

### 2.4 变量角色绑定

原问题：自然语言中的变量角色经常和 Lean 参数顺序错位，尤其是整除、因子、倍数、向量组个数、空间维数、秩之间的关系。

本次实现：

新增 `extract_role_bindings(node)`，当前支持：

- `b 是 a 的因子` -> `divisor = b`，`dividend = a`。
- `b 整除 a` -> `divisor = b`，`dividend = a`。
- `a 是 b 的倍数` -> `b ∣ a`。
- `含 s 个向量` -> `cardinality = s`。
- `n 维` -> `ambient_dimension = n`。
- `向量组秩` -> 标记为 span dimension，避免混入矩阵秩。

能解决的问题：

- 报告3 Item 3：整除定义中除数和被除数顺序颠倒。
- 报告3 Item 8、10：公因子、公倍数中角色容易反。
- 报告2 Item 36：`s≤n` 与 `s≤r` 这类变量角色混淆。
- 报告1 Item 34、40：向量组秩与矩阵秩语境混淆。

### 2.5 语义风险检查

原问题：现有流程主要看编译是否通过，难以及时标出“编译过但语义不保真”的结果。

本次实现：

新增 `check_formalization_risks(node, lean_code="")`。如果没有 Lean 输出，也会检查源文本风险；如果传入 Lean 代码，则能进一步检查：

- `wrong_connector`: 逻辑连接词不匹配。
- `extra_condition`: 添加了原题未要求的非零/正性条件。
- `concept_downgrade`: 关键概念被降级替换。
- `api_context_mismatch`: API 与数学对象语境不一致。
- `definition_as_implementation`: 定义类节点被实现函数替代。
- `strict_inclusion_mismatch`: 非严格包含被改成严格包含。
- `role_reversal`: 整除等角色顺序风险。
- `ocr_suspicious_text`: 源文本疑似 OCR 错误。

能解决的问题：

- 报告1 Item 37：“获相等”疑似 OCR 错误，应先修文本。
- 报告3 Item 9、10、13：M2 添加原题没有的非零、正性条件。
- 报告1/2 中“编译通过但语义错误”的大部分类型可以先被风险标签召回。

### 2.6 降低纯规则测试的环境依赖

原问题：导入 `pipeline.common` 会立刻导入 LLM 相关依赖，导致只测试纯规则模块时也需要安装 `dotenv`。

本次实现：

修改：

```text
backend/pipeline/common/__init__.py
```

将 `run_multiprocess_task` 改成懒导入。这样纯规则模块可以在没有 LLM 环境依赖时单独测试。

## 三、针对原实验样本的覆盖关系

| 问题类型 | 原实验样本 | 本次修改对应机制 | 预期效果 |
|---|---|---|---|
| 例子类命题误用蕴含 | 报告1 Item 39 | `example_conjunction` 骨架 + `wrong_connector` 风险 | 提醒使用 `∧` 表示多个事实同时成立 |
| 向量组秩 API 不当 | 报告1 Item 34/40；报告2 Item 34 | `vector_family_rank` 概念词典 | 抑制默认使用 `Matrix.rank` |
| 子命题/等价结构丢失 | 报告2 Item 11/13；报告3 Item 12/13 | `equivalence`、`multi_part` 骨架 | 标记单向化、漏推论、强行合并 |
| 整除变量顺序错误 | 报告3 Item 3 | `divisibility_roles` + `role_bindings` | 明确 `divisor ∣ dividend` |
| 相伴关系被降级 | 报告3 Item 6 | `associated` 概念词典 | 标记 `IsUnit` 替代 `Associated` 的风险 |
| GCD/LCM 定义被实现替代 | 报告3 Item 9/11 | `gcd_definition`、`lcm_definition` | 提醒定义类节点展开谓词，不直接调函数 |
| 额外添加非零/正性条件 | 报告3 Item 9/10/13 | `extra_condition` 风险 | 标记题目没有的额外条件 |
| 非严格包含误写严格包含 | 报告3 Item 22 | `non_strict_chain` 骨架 + `strict_inclusion_mismatch` | 提醒 `⊆` 不能自动改 `<` |
| OCR 错误传导 | 报告1 Item 37 | `ocr_suspicious_text` 风险 | 在 formalizer 前提示先修文本 |
| M2 上下文干扰 | 报告1 Item 24/27/41；报告3 Item 9/10/13 | M2 分层 payload + context policy | 正文优先，标题/标签只辅助消歧 |

## 五、验证情况

已运行：

```bash
python3 backend/scripts/test_formalization_guards.py
python3 -m py_compile backend/pipeline/common/formalization_guards.py backend/pipeline/stages/extract_logic_tuples/stage.py backend/scripts/test_formalization_guards.py
```

测试覆盖：

- 充分必要条件识别为 `equivalence`。

- M2 分层 payload 能保留正文优先、标题辅助。
- “获相等”会被标为 OCR 可疑文本。

## 六、当前局限与下一步

本阶段主要是“风险标记与结构提示”，还没有直接重写 Lean 输出，也没有实现 M1/M2 双路自动选择。因此它的直接收益是提高可解释性、减少盲目送入 formalizer 的风险、为下一阶段候选选择提供分数依据。

下一阶段建议继续做：

1. 将 `build_formalizer_context_payload` 接到实际 formalizer v3 的 M2 prompt 构造处。
2. 让 formalizer 输出 Lean 后调用 `check_formalization_risks(node, lean_code)`。
3. 在 M1/M2 都生成时，根据编译结果、骨架一致性、概念风险和额外条件风险做候选排序。
4. 用三份实验报告中的已知错误样本回放，统计风险标签召回率和误报率。
