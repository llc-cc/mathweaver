## 典型案例深度分析

### Item 3: 整除的定义（M2胜）

**题目**: 设 $a, b \in R$，如果存在 $c \in R$ 使得 $a = bc$，则称 $b$ 整除 $a$，记作 $b \mid a$。

**M1**: `def divides a b := ∃ c, a = b * c` → 对应 `a | b`，**与题目相反**
**M2**: `def divides a b := ∃ c, a = b * c` → 同样错误

**问题**: 题目说 "b 整除 a" 即 $b \mid a$，对应 $a = bc$。但两个 M1/M2 都定义成 `∃ c, a = b * c`（即 $a \mid b$ 的定义）。变量顺序颠倒。

**改进建议**: M1/M2 prompt 应明确区分"被除数"和"除数"的角色，避免变量顺序与日常语言不一致。

---

### Item 6: 不可约元的定义（平）

**题目**: 若 $a = bc$ 蕴含 $b ∼ a$ 或 $b ∼ 1$，则 $a$ 为不可约元。（`~` 表示相伴关系：$b \sim a \iff b = ua$ 对某个单位 $u$）

**M1/M2**: `a = b * c → IsUnit b ∨ IsUnit c`

**问题**: 题目用相伴关系 `~`（等价关系），M1/M2 用 `IsUnit`（仅判断是否为单位）。$b \sim a$ 意味着 $b = ua$（$u$ 为单位），这比"仅仅是 $b$ 为单位"更强。

**改进建议**: 应使用 `Associated` 谓词而非 `IsUnit`。

---

### Item 9: 最大公因子的定义（平，都错）

**题目**: $d$ 为 $a, b$ 的最大公因子，当且仅当 $d \mid a$ 且 $d \mid b$，且对任意 $c$，若 $c \mid a$ 且 $c \mid b$ 则 $c \mid d$。

**M1**: 直接用 `GCDMonoid.gcd` 函数（实现而非定义）
**M2**: 添加了题目未要求的 `a≠0 ∨ b≠0` 和 `d>0`

**问题**: M1 直接用工具函数而非形式化定义；M2 过度添加约束。

**改进建议**: 应严格按题目形式化为谓词定义，不添加额外约束。

---

### Item 22: 理想升链的定义（平，都错）

**题目**: 理想升链 $N_1 \subseteq N_2 \subseteq \cdots$（非严格包含）

**M1/M2**: 使用严格包含 `N_i < N_{i+1}`

**问题**: 题目说 $\subseteq$（允许相等），M1/M2 用 `<`（严格递增）。

**改进建议**: prompt 应明确区分 `⊆` 和 `⊂` 的区别。

## 结论与改进建议

### 结论

1. **M2 语义通过率 75%（21/28）高于 M1 67.9%（19/28）**
2. **M2 在编译成功率和语义正确率上均优于 M1**
3. **主要语义错误类型**:
   - 变量顺序与题目不符（Item 3）
   - 丢失关键数学概念（相伴关系 `~` vs `IsUnit`，Item 6）
   - 过度泛化/添加题目未要求的条件（Item 9, 10, 22）
   - 逻辑结构与原题不符（Item 12, 13）
   - 直接使用 Mathlib 工具函数而非形式化定义（Item 9, 11）

### 改进建议

1. **变量顺序规范**: 在 prompt 中明确"被除数"和"除数"的对应关系，避免日常语言与 Lean 变量顺序混淆

2. **关键数学概念保留**: 不可约元的"相伴关系"应使用 `Associated` 而非 `IsUnit`

3. **严格遵循题目条件**: 避免添加题目未明确要求的条件（如正性约束、非零约束）

4. **定义 vs 实现分离**: 当题目要求"定义"时，应形式化为命题定义而非调用 Mathlib 工具函数

5. **GTED 评估升级**: 轮次管理应使用 Lean LSP hover-based GTED（而非旧的 tokenization 方法），确保评估结果有效

6. **逻辑结构一致性**: 对于多子命题的题目（如"充分必要条件 + 推论"），应完整编码所有子命题
