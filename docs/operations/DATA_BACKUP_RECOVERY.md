# 数据备份、恢复与演练手册

本文定义 MathWeaver 生产数据的备份责任、恢复步骤和可量化验收门槛。数据库连接串和 OSS 凭据只能通过受保护的后端环境文件或密钥服务注入，不得写入命令行、工单、聊天记录或本手册。

## 1. 责任与证据

| 角色 | 责任 | 每次发布或演练必须留存的证据 |
| --- | --- | --- |
| 服务负责人 | 批准 RPO/RTO、维护恢复顺序、签署最终验收 | 发布版本、Alembic revision、验收结论 |
| RDS 管理员 | 自动备份、日志备份、PITR 和隔离恢复实例 | 策略截图、备份 ID、恢复实例 ID、恢复时间线 |
| OSS 管理员 | 私有 Bucket、版本控制、复制和对象恢复 | Bucket 策略版本、复制状态、恢复前缀、抽检结果 |
| 值班工程师 | 执行应用验证、记录告警和失败处置 | 命令退出码、无敏感信息日志、健康检查结果 |
| 安全负责人 | 审核最小权限、密钥轮换和证据访问权限 | RAM/RDS 权限审计、轮换记录、证据保留位置 |

证据保存在受访问控制的发布/演练记录中，至少保留 12 个月。任何证据不得包含数据库 URL、密码、AccessKey、模型 Key、会话令牌或签名 URL。

## 2. 生产门槛

首次上线前必须满足以下最小目标；若业务 SLO 更严格，以业务 SLO 为准：

- RDS 自动备份和日志备份已启用，保留期不少于 14 天；PITR 目标 RPO 不超过 5 分钟。
- RDS 从选定恢复点创建新实例至验证脚本通过的 RTO 不超过 120 分钟。
- OSS Bucket 已启用版本控制；跨区域复制延迟抽检不超过 15 分钟。
- OSS 从版本/副本恢复到隔离前缀并完成对象哈希抽检的 RTO 不超过 240 分钟。
- 整体服务从宣布恢复到 `/health`、登录、历史读取和对象恢复验收通过的 RTO 不超过 240 分钟。
- 每季度至少完成一次 RDS + OSS 联合恢复演练；发生重大 schema、对象 manifest 或密钥格式变更后追加一次演练。

未达到目标时不得用“备份任务成功”代替恢复证据。服务负责人必须记录实际 RPO/RTO、差距、责任人和整改截止日期。

## 3. 发布前备份检查

1. 记录应用镜像、迁移镜像、Git 提交和当前 Alembic revision。
2. 在 RDS 控制台确认最近自动备份成功、日志链连续且可选择目标恢复时间。
3. 创建发布前手动快照，记录备份 ID，不覆盖或删除旧恢复点。
4. 记录恢复基线：`history` 总行数、未删除/已删除行数和各 `storage_status` 行数。
5. 确认 OSS 版本控制及复制状态正常，目标 Bucket/前缀仍为私有。
6. 选取固定样本记录其 manifest checksum；对象哈希证据保存在受控记录中。
7. 确认恢复操作使用独立 RDS 实例、隔离 OSS 前缀和非 root 部署账号。

## 4. 季度联合恢复演练

### 4.1 恢复 RDS

1. 选择演练恢复点并记录其时间、备份 ID 与预计数据截止时间。
2. 恢复到新的 RDS 实例或新的独立 `mathweaver` 数据库；禁止覆盖生产库，禁止指向 `uniprism_alphatest_user`。
3. 使用只授权给演练库的最小权限账号，确认 `SELECT DATABASE()` 为 `mathweaver`。
4. 检查 Alembic revision 与演练应用/迁移镜像兼容；不要在事故中盲目执行 downgrade。
5. 将恢复数据库 URL 只写入权限为 `600` 的临时后端环境文件。

### 4.2 恢复 OSS

1. 从指定版本或跨区域副本恢复到隔离演练前缀，不写回生产任务前缀。
2. 保持 Bucket 私有，演练 RAM 账号只拥有隔离前缀的列举、读取和必要写入权限。
3. 验证数据库记录指向的版本存在，manifest 的用户、任务、版本和 checksum 与数据库一致。
4. 对确定性样本验证 manifest 中每个对象的大小与 SHA-256；缺少 manifest 的版本不得视为可恢复。
5. 演练结束后按审批清理隔离前缀；生产版本和证据样本不得删除。

### 4.3 执行无敏感信息校验

先在当前 shell 安全注入恢复环境所需变量，禁止把连接串作为参数传入：

```powershell
$env:MATHWEAVER_DATABASE_URL = '<从受控密钥源注入>'
$env:MATHWEAVER_OBJECT_STORAGE = 'oss'
./deploy/verify-restored-data.ps1 -ExpectedHistoryRows <发布前记录的总行数>
```

需要抽检远端对象时，在同一受保护环境中直接调用核心验证命令：

```powershell
python backend/scripts/verify_restored_data.py `
  --expected-history-rows <发布前记录的总行数> `
  --sample-size 25 `
  --verify-objects
```

验证输出只能包含数量、状态、稳定错误码和校验结论，不得包含数据库 URL、OSS 对象签名 URL 或凭据。

## 5. 恢复验收标准

以下项目必须全部通过：

- `history` 总行数与发布前基线完全相等。
- 未删除、已删除以及每个 `storage_status` 的行数与基线完全相等。
- 抽检样本的 manifest checksum 100% 与数据库一致，样本数不少于 25；不足 25 条时全量检查。
- 开启对象校验时，样本内文件大小和 SHA-256 100% 通过，不允许缺失对象或越权前缀。
- 数据库中不存在指向缺失版本的可见历史，隔离前缀中不存在本次恢复产生的未登记可见版本。
- `/health`、登录、历史摘要、历史详情、源 PDF/导出恢复各完成一次成功验证。
- 实测 RPO/RTO 已记录并满足第 2 节目标。

任一校验失败即判定恢复失败。保持生产流量关闭，不修改原生产实例；保留恢复实例、日志和对象样本供调查，修复后从新的干净恢复点重新演练。
