# MathWeaver 网页端账号与 MySQL 中心化设计

> 日期：2026-08-21  
> 状态：待用户最终审核  
> 目标项目：`D:\ywkeji\pdfPipeline-main`  
> 首期目标：网页端集中访问、学号或邮箱登录、阿里云 MySQL 持久化

## 1. 背景与目标

MathWeaver 0.1.1 已具备 React 网页前端、Flask API、邮箱密码登录、任务历史和证明工作区，但当前使用本机 SQLite，账号允许自行注册，也没有学生、教师和管理员角色。

本次改造以网页端为正式交付形态：用户通过浏览器访问部署在阿里云服务器上的 MathWeaver，结构化业务数据统一写入阿里云 RDS MySQL。现有 Electron 桌面打包不作为本阶段上线入口，但不得因网页端改造而被无关破坏。

首期完成账号、权限、数据中心化和管理员导入；教师查看学生详情作为下一阶段功能，但首期建立其所需角色与课程关系基础。

## 2. 已确认需求

- 在现有阿里云 MySQL 实例中新建独立数据库 `mathweaver`。
- 不修改现有 `uniprism_alphatest_user` 数据库及其业务表。
- 账号角色包含学生、教师和管理员。
- 学生学号必填且唯一。
- 邮箱可选；填写后必须唯一。
- 登录框允许输入学号或邮箱。
- 关闭前台自行注册。
- 管理员通过 CSV 批量导入学生。
- 学生使用初始密码首次登录后收到修改提示，但可以暂不修改。
- 用户可以主动修改密码。
- 管理员可以重置密码。
- 密码只保存安全哈希，不保存可逆明文。
- 登录会话具有明确有效期，退出后当前会话立即失效。
- 历史、任务进度和证明工作区写入 MySQL。
- 数据库凭据只从环境变量读取。
- 新增和实质修改的模块、异步流程及安全分支写简洁中文注释，并补自动化测试。

## 3. 方案选择

### 3.1 采用方案

在现有后端中增加独立数据库访问层和版本化迁移，将认证、会话、历史及证明工作区逐步从直接调用 `sqlite3` 改为统一存储接口。

选择原因：

- 保留现有前端、API 和知识图谱流水线，改动范围可控；
- 数据库逻辑不继续堆积在大型 `api_v2.py` 中；
- 可以针对 MySQL 做连接池、事务和迁移；
- 便于后续增加教师查询、课程关系和审计；
- 测试时可以替换存储实现，降低认证测试成本。

### 3.2 不采用的方案

不在 `api_v2.py` 中逐条把 SQLite SQL 改成 MySQL SQL。该方式初期看似快，但会继续混合路由、权限、业务决策和持久化，迁移失败难以回滚，也不符合项目开发约定。

本期也不拆分独立微服务。新服务会增加部署、鉴权和联调成本，不符合当前时间要求。

## 4. 系统架构

```text
浏览器
  → HTTPS 反向代理
  → React 网页前端
  → Flask API
      ├─ 认证与权限服务
      ├─ 学生批量导入服务
      ├─ 历史与证明工作区服务
      ├─ 现有 OCR/知识图谱流水线
      └─ MySQL 数据访问层
            → 阿里云 RDS MySQL / mathweaver
```

生产环境中数据库仅允许服务器内网访问。浏览器永远不直接连接 MySQL，也不会获得数据库凭据。

## 5. 数据模型

### 5.1 用户与会话

`users`：

- `id`：主键；
- `student_no`：学生学号，可空但学生角色必须填写，唯一；
- `email`：可空，填写后唯一；
- `display_name`：姓名；
- `role`：`student`、`teacher` 或 `admin`；
- `password_hash`：密码哈希；
- `initial_password_pending`：是否仍在使用初始密码，仅用于显示提示；
- `is_active`：账号是否启用；
- `created_at`、`updated_at`。

`sessions`：

- `token_hash`：会话令牌哈希，不保存原始令牌；
- `user_id`；
- `expires_at`；
- `created_at`；
- `revoked_at`；
- 最近使用时间和必要的客户端信息。

教师和管理员不要求填写学号，可以使用邮箱登录。学号与邮箱的输入空间必须避免歧义：若某个登录值同时匹配一人的学号和另一人的邮箱，系统拒绝建立冲突账号。

### 5.2 教学关系基础

首期建立但不开发完整教师界面：

- `courses`：课程；
- `classes`：教学班；
- `class_memberships`：学生、教师与教学班关系。

这保证第二阶段无需重构用户表即可实现“教师只能查看所辖学生”。

### 5.3 学习数据

保留现有业务含义并迁移到 MySQL：

- `history`：图谱结果、任务状态、阶段和原文元数据；
- `user_settings`：模型配置元数据；
- `proof_workspaces`：证明草稿、版本、AI 消息和导入记录。

大体积 PDF、处理缓存和导出包不写入 MySQL BLOB。首期保存在服务器受控数据目录，并在数据库保存对象标识和元数据；后续可无缝切换 OSS。MySQL 只保存结构化数据和体积可控的 JSON。

## 6. 登录与密码流程

### 6.1 登录

登录页提供一个“学号或邮箱”输入框和密码输入框。后端统一规范化输入后查询：

- 包含 `@` 时优先按规范化邮箱匹配；
- 否则优先按精确学号匹配；
- 不向客户端暴露“账号不存在”还是“密码错误”；
- 停用账号不能登录；
- 登录成功返回原始会话令牌，此令牌仅在客户端持有，数据库保存其哈希。

### 6.2 初始密码提示

管理员导入或重置密码后，`initial_password_pending` 为真。用户登录成功后正常进入系统，同时显示非阻塞提示：

> 当前仍在使用初始密码，建议尽快修改。

用户可立即修改或暂时关闭提示。关闭提示不清除标记；只有成功修改密码后才清除标记。

### 6.3 修改和重置

- 用户修改密码必须验证当前密码；
- 新密码满足统一密码规则；
- 修改成功后撤销该用户其他活动会话，当前会话可重新签发；
- 管理员重置密码时生成一次性展示的临时密码；
- 服务端只在响应中返回一次临时密码，不写日志、不写数据库明文；
- 重置后撤销用户全部现有会话。

## 7. CSV 批量导入

首期 CSV 字段：

```text
student_no,display_name,email,class_code,initial_password
```

规则：

- `student_no`、`display_name` 必填；
- `email`、`class_code` 可选；
- `initial_password` 可选；未提供时由系统安全生成；
- 先完整校验，再用单个事务写入；
- 文件内重复、数据库冲突、邮箱格式错误和缺少字段都会生成明确行号错误；
- 默认不覆盖已有账号；
- 返回成功数、失败数和可下载的错误明细；
- 仅管理员可以导入。

## 8. API 变化

保留 `/api/v2` 前缀，首期调整或新增：

- `POST /api/v2/auth/login`：`identifier + password`；
- 移除或禁用公开的 `POST /api/v2/auth/register`；
- `GET /api/v2/auth/me`：返回用户标识、姓名、角色和初始密码提示状态；
- `POST /api/v2/auth/change-password`；
- `POST /api/v2/auth/logout`；
- `POST /api/v2/admin/users/import`；
- `POST /api/v2/admin/users/{id}/reset-password`；
- `PATCH /api/v2/admin/users/{id}/status`。

所有管理员接口都在后端校验角色，不能只依靠前端隐藏按钮。

## 9. 数据迁移

采用版本化 SQL 迁移，至少包含：

1. 创建数据库表、索引和约束；
2. 创建角色、课程和教学班基础表；
3. 提供 SQLite 数据迁移脚本，将现有用户、历史和证明工作区迁入 MySQL；
4. 迁移前只读备份 SQLite；
5. 迁移后核对用户数、历史数、证明工作区数和关键外键；
6. 迁移失败时事务回滚，不删除原 SQLite 文件。

旧邮箱用户没有学号时保留为兼容账号，由管理员后续补充学号或分配角色。

## 10. 配置与安全

后端通过环境变量读取：

```text
MATHWEAVER_DB_HOST
MATHWEAVER_DB_PORT
MATHWEAVER_DB_NAME
MATHWEAVER_DB_USER
MATHWEAVER_DB_PASSWORD
MATHWEAVER_SESSION_TTL_SECONDS
MATHWEAVER_ALLOWED_ORIGINS
```

- `.env` 不提交版本库；
- 提供无敏感信息的 `.env.example`；
- MySQL 使用专用账号和最小权限；
- 生产环境限制 CORS；
- 登录、导入和密码重置记录安全审计事件；
- 日志不得包含密码、会话令牌或模型 API Key；
- 任务结果、源 PDF、导出和 OCR 接口补齐登录与所有权校验。

## 11. 前端改造

- 登录文案由“邮箱”改为“学号或邮箱”；
- 移除创建账号入口；
- 登录后保存用户显示名、角色和提示状态；
- 增加初始密码非阻塞提示；
- 增加修改密码界面；
- 增加管理员学生导入和重置密码的最小页面；
- 学生看不到管理员入口；
- 所有权限仍以后端判断为准。

## 12. 错误处理

- 数据库不可用时返回统一服务不可用错误，不回退到本机 SQLite 继续写入；
- 导入采用全量预校验，避免半批数据写入；
- 唯一键冲突返回可理解的字段错误；
- 会话过期或撤销统一返回 401，前端清理本地认证状态；
- 权限不足返回 403；
- 迁移和导入日志不记录敏感字段。

## 14. 实施边界

本设计首期不包含：

- 强制首次修改密码；
- 邮件或短信验证码；
- 邮件找回密码；
- 学校统一身份认证；
- 完整教师数据看板；
- 自动评分和课程成绩；
- 微服务拆分；
- 多节点任务队列和大规模 OCR 集群；
- OSS 文件迁移。

这些能力不阻止首期网页端账号与 MySQL 中心化上线，可在后续阶段独立建设。
