# 学生证明学习上下文管理设计说明

## 一、设计目标

学生的每次证明提问都应当被视为连续学习过程的一部分，而不是孤立的问答。上下文管理的目标是：

1. 保存学生学习过程中的原始事实，保证可以回溯；
2. 将事实整理为可复用的结构化学习状态；
3. 通过知识图谱把一个知识点上的学习判断关联到相邻知识点；
4. 在每次提问时按相关性选择历史信息，避免重复携带整段对话；
5. 在上下文压缩后仍保留当前目标、未解决问题、重要纠正和依据来源。

核心原则是“原始记录与派生判断分离、事实与假设分离、当前作业状态与长期知识状态分离”。

## 二、上下文的分层结构

上下文采用“原始交互—学习依据—知识点状态—课程概况—提问上下文”的五层结构。

### 1. 原始交互层

记录学生在一次提问中的完整学习事实：

- 当前知识点和证明目标；
- 学生提交的证明草稿；
- 学生选择的动作，如提示、检查或总结；
- 辅导回答；
- 提问发生的时间和所属课程作业。

该层是不可替代的事实来源。任何压缩、总结或重新判断都不能覆盖原始交互。

### 2. 学习依据层

从原始交互中提取可独立复核的学习判断。依据类型包括：

- 学习目标；
- 已掌握内容；
- 理解偏差；
- 知识缺口；
- 使用的知识；
- 学习提示；
- 待解决问题；
- 证明思路。

每条依据都应具有来源、可信度、严重程度、产生时间和处理状态。处理状态包括“开放、已确认、已解决、不准确”。

“开放的理解偏差或知识缺口”可以参与后续提问；“已解决”或“不准确”的旧判断只能作为历史记录，不能继续作为当前事实。

### 3. 知识点状态层

以课程内稳定的知识点为单位聚合学习依据，形成学生在该知识点上的状态：

- 当前目标和已掌握内容；
- 仍然存在的理解偏差和知识缺口；
- 已使用的定理、定义或证明方法；
- 关联知识点带来的复习提醒；
- 当前待解决问题数量和最近变化。

该层描述的是跨作业的知识学习状态，不等同于某一次作业是否完成。完成作业、提交答案和真正掌握应当分别记录。

### 4. 课程概况层

在多个知识点状态之上形成课程级概况，主要包括：

- 学生已经接触和掌握的知识点范围；
- 需要重点复习的知识点数量；
- 反复出现的理解偏差和知识缺口；
- 最近发生变化的知识点；
- 可以作为后续学习入口的知识点。

课程概况用于跨作业建立连续性，但不替代知识点级别的具体依据。

### 5. 提问上下文层

这是每次提问时临时组装的上下文，不作为新的事实层长期保存。它根据当前问题选择前四层中最相关的内容，供辅导回答和学习判断使用。

## 三、每次提问应进入哪些内容

每次提问的上下文分为“固定内容”和“历史内容”。

### 固定内容

以下内容必须始终进入上下文：

- 当前知识点的陈述、目标、条件和结论；
- 学生当前的证明草稿；
- 本次动作和问题意图；
- 当前知识点尚未解决的直接问题；
- 学生已经纠正或确认的关键信息。

### 历史内容

历史内容按照相关性选择，包括：

1. 当前知识点最近的学习进展；
2. 最近四次原始交互的必要片段；
3. 当前知识点的已掌握内容、理解偏差、知识缺口和使用方法；
4. 一跳前置知识、后续知识和其他强关联知识中与本次问题有关的依据；
5. 同一课程跨作业的知识点状态和课程概况；
6. 已解决、不准确或重新打开的处理记录，用于防止旧判断被重复使用；
7. 每项判断的来源、时间、状态和记录编号。

历史内容按照以下四个因素排序：

> 未解决程度 × 知识关系强度 × 依据可信度 × 时间新鲜度

当前目标、直接的未解决问题、教师确认的判断和学生主动纠正的内容具有最高优先级。

## 四、跨知识点关联规则

### 1. 关联范围

默认只将当前知识点的直接学习判断传播到一跳关联知识点：

| 关联类型 | 默认权重 | 含义 |
| --- | ---: | --- |
| 当前知识点直接记录 | 1.00 | 当前问题本身的学习判断 |
| 前置知识提醒 | 0.75 | 可能需要回顾的基础知识 |
| 后续知识提醒 | 0.55 | 可能影响后续学习的知识 |
| 其他强关联知识 | 0.35 | 与当前问题相关但非直接依赖的知识 |

最终权重还要乘以依据本身的可信度。两跳及更远的知识点只用于检索候选信息，不直接写入学生的持久状态。

### 2. 风险与事实的区分

如果学生在知识点 A 上出现理解偏差，知识点 B 只能得到“可能需要复习”的提醒，不能直接被标记为错误或未掌握。只有 B 上出现了自己的直接学习依据，B 的掌握状态才可以发生直接变化。

每条关联提醒都应说明关联原因，例如：

- 可能需要回顾的前置知识；
- 后续知识提醒；
- 相关知识。

### 3. 可信度规则

学习判断的可信度按照以下顺序提高：

1. 教师确认；
2. 经审核的考核结果；
3. 多次一致的直接表现；
4. 单次辅导判断；
5. 学生自我描述。

低可信度判断可以进入复习建议，但不能单独改变相关知识点的掌握结论。

## 五、上下文压缩规范

### 1. 压缩原则

压缩只改变后续提问时的携带方式，不删除原始交互，也不覆盖原始回答。所有总结必须能够通过原始交互和学习依据重新生成。

### 2. 分层保留策略

- 最近四次交互保留必要原文片段；
- 每个知识点累计 8 次新交互或约 6000 tokens 后，生成知识点小结；
- 累计 10 个知识点小结发生变化后，更新课程概况；
- 更早的交互使用结构化小结代替完整文本；
- 已解决、已撤回、重复或与当前问题无关的内容优先缩短。

### 3. 历史预算

历史上下文默认预算为 6000 tokens，不包括当前知识点、当前草稿和本次动作。超出预算时按照以下顺序处理：

1. 删除最早、相关性最低的原始交互片段；
2. 删除低相关度的关联知识内容；
3. 将课程概况降级为数量和重点知识点；
4. 删除较长的依据摘录；
5. 缩短依据陈述，但保留其类型、状态和记录编号；
6. 对仍无法放入的内容保留引用编号，供后续追溯。

### 4. 压缩后的不可丢失项

以下内容不能因为压缩而删除：

- 当前证明目标；
- 当前知识点的直接未解决问题；
- 教师确认的学习判断；
- 学生主动纠正或撤回的记录；
- 当前回答所依赖的知识点；
- 每条保留判断的来源和记录编号。

### 5. 摘要的规范

知识点小结和课程概况必须保持结构化，至少包含学习目标、已掌握内容、理解偏差、未解决的知识缺口、使用过的知识、下一步建议、已处理记录以及对应的学习记录编号。

每份小结还应记录覆盖范围、生成时间、规则版本和内容规模，保证规则调整后可以重新生成，而不是依赖无法核验的一段自然语言总结。

## 六、纠正与状态更新

学生可以对系统整理出的学习判断进行“不准确、已解决、重新打开”操作。每次操作都会生成新的处理记录，并重新计算相关知识点的状态。

状态更新遵循以下顺序：

1. 保留旧判断及其处理历史；
2. 将新的学生反馈作为最新状态；
3. 从后续提问中排除已经解决或不准确的旧判断；
4. 必要时重新生成知识点小结和课程概况。

这样既保留学习过程，又避免错误判断持续影响后续辅导。

## 七、前端呈现原则

### 学生端

学生端使用“学习情况”等教学语言，展示当前目标、已掌握内容、还需解决、相关知识复习提醒和下一步建议。每条关联提醒都能查看原因，并允许学生纠正。

### 教师端

教师端使用“学生掌握情况”和“学习诊断”，展示需要重点复习的知识点、相关知识提醒、学习判断依据和短片段。默认不展示完整对话，避免把系统内部判断直接当成最终结论。

### 图谱提示

图谱只显示轻量状态：直接问题和关联复习提醒使用不同样式，明确区分“当前回答中发现的问题”和“由知识关系得到的复习建议”。

## 八、设计结论

这套设计不是保存单个知识点的聊天记录，而是建立一条可持续更新的学习链路：

```text
原始提问
  → 学习依据
  → 知识点状态
  → 关联知识提醒
  → 课程学习概况
  → 下一次提问的针对性辅导
```

它同时满足三项要求：

- 对学生：每次提问都能从已有学习进展继续；
- 对教师：可以看到掌握变化及其依据；
- 对系统：上下文有明确层次、优先级和压缩边界，且任何判断都可以回到原始记录核验。
